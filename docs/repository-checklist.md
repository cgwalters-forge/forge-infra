# Repository checklist

> This text was generated by an LLM ([how cgwalters uses LLMs](https://github.com/cgwalters/cgwalters#llms)). cgwalters has not reviewed it yet.

What a repository in cgwalters-forge should have. Follow it when creating
one, and check existing repositories against it when something here
changes; not every existing repository matches it yet.

## Scope

These policies and procedures apply only to first-party repositories: those
whose `origin` custom property is `first-party`, matching the search filter
`org:cgwalters-forge props.origin:first-party`
([list](https://github.com/search?q=org%3Acgwalters-forge+props.origin%3Afirst-party&type=repositories)).
Repositories with `origin` set to `fork` (a GitHub fork of another project,
the `bot-midstream` mirrors included) or `mirror` (a copy of a project hosted
elsewhere, such as base-images) follow their upstream's conventions and get
none of this, even where an agent wrote the text.

Set `origin` when creating a repository, from the start: `first-party` for
our own projects, `fork` for a GitHub fork, `mirror` for a mirror that is not
one. A repository without a value is out of scope until it has one.

First-party and forked repositories may later move to separate
organizations; until then this property is the line between them.

## Name and visibility

A repository whose name ends in `-sandbox` is for agents to iterate in
freely: the organization's approval ruleset excludes it, so its pull
requests merge without a review. Renaming it to drop the suffix brings it
under the ruleset, so the review below must be in place before the rename.

Everything else is under the organization's approval ruleset from its first
pull request: `main` requires one approving review, and an approval is
dismissed when new commits are pushed.

## About

- **Description**: one sentence saying what it is, not how it is built.
- **Homepage**: the project's site when it has one. A repository that
  publishes GitHub Pages sets its homepage to the Pages URL
  (`https://cgwalters-forge.github.io/<name>/`) in the same change that
  turns Pages on, so the site is one click from the repository.
- **LLM notice**: every generated document carries the notice below as
  the first line under its title (see "Generated documents").
- **License**: Apache-2.0 unless the project says otherwise (agent-board's
  Rust crates are dual Apache-2.0 and MIT).

## Review

Put the review caller and its three files in the **initial commit**, copied
from an onboarded repository (agent-board or this one) and adapted:

- `.github/workflows/review.yml`, calling
  `cgwalters-forge/actions/.github/workflows/cgwalters-review.yml` at the
  commit the other repositories pin;
- `workflow/review.toml` and `workflow/review-command.toml`, with `repos`
  naming this repository;
- `workflow/review.md`, whose opening says what this repository's changes
  can affect, so the reviewer knows what to weigh. A repository with
  dependency manifests keeps the paragraph on manifest and lockfile changes
  as supply-chain changes.

The first push to an empty repository is not a pull request, so the review
is in place before the ruleset first applies. Added later, the onboarding
pull request needs an organization owner's approval, because nothing can
review it yet.

At creation, also:

- set the repository variables the actions README lists under "Review",
  copied from agent-board: `AGENT`, `AGENT_MODEL`, `AGENT_RUNNER`,
  `AGENT_CONFIG_REPO`, `AGENT_CONFIG_PATH`, `INFERENCE_AUDIENCE`,
  `INFERENCE_URL`, `AGENT_REAL_REVIEWS=true`, and `REVIEW_BOT_IDS` when
  Dependabot's pull requests should be reviewed. Copy only these; tracker
  has more that are specific to its own workflows;
- allow GitHub Actions to approve pull requests (Settings, Actions,
  General), without which `AGENT_REAL_REVIEWS` cannot submit the approval.

## Generated documents

Every Markdown document an LLM wrote or substantially rewrote, READMEs and everything under `docs/` included, starts
with this notice as the first
line under its title:

```markdown
> This text was generated by an LLM ([how cgwalters uses LLMs](https://github.com/cgwalters/cgwalters#llms)). cgwalters has not reviewed it yet.
```

Keep the first sentence exactly as written, so the notice can be found by
search. Never name a model, provider or tool: nearly every document is the
work of several. Context may follow in further sentences, such as "Nothing
in it was run." When cgwalters has reviewed the text, the second sentence
says so, or the notice goes.

Files that are input to an agent rather than documents for people
(`AGENTS.md`, `CLAUDE.md`, skills' `SKILL.md`, review and task prompts under
`workflow/`), issue and pull request templates, test fixtures, and license
and notice files don't carry it.

## CI and the repository ruleset

Every repository has a `ci` workflow whose last job, also named `ci`,
needs every other job and fails unless they all succeeded, so the ruleset
can require that one check whatever jobs CI grows. At the least it runs the
shared workflow lint, `cgwalters-forge/actions/lint@main` (actionlint,
zizmor and the runner-label policy); this repository's
[ci.yml](../.github/workflows/ci.yml) is the minimal form.

The organization ruleset only requires the approval. Each repository adds
its own ruleset on the default branch, as agent-board's "main: PR with
green ci, linear, no force-push or deletion" does:

- required status check `ci` (from GitHub Actions), not strict: the merge
  queue tests each pull request on top of `main` instead of requiring
  branches to be up to date;
- a merge queue, rebase method, all entries green;
- rebase as the only allowed merge method, and linear history;
- no deletion and no force push.

In repository settings, allow only rebase merging, delete head branches on
merge, and allow auto-merge.

## Actions

- Default workflow token permissions: read, as in agentic-job; each
  workflow and job asks for what it needs.
- Pin third-party actions by commit. Our own (`cgwalters-forge/*`) follow
  `main`, or a release tag for agentic-job; the review wrapper is pinned by
  commit, so the merge gate changes only by a reviewed change. Copy
  `.github/zizmor.yml`, which states that policy for zizmor, and
  `.github/actionlint.yaml` from this repository.
- `.github/dependabot.yml` moves third-party action pins, with a 7-day
  cooldown.
- `.github/agentic-job/workflows.toml` exempts the review caller and any
  other workflow that cannot take the job shapes `agentic-job workflows
  check` admits, each with its reason, so the organization's workflows-check
  (actions' lint/workflows-check.md) passes once it is required. An
  exemption must name a file that is already on the base branch, so it goes
  in the same initial commit.
- A repository that publishes a site builds it under secure-host and
  deploys it from a separate deploy-only job, the shape the check admits
  (agentic-job's docs/workflows-check.md); then it needs no exemption.

## Letting agents work here

Before dispatching runs to the repository, add it to tracker:

- `repos` in `.github/agentic-job/dispatch.toml` and `fix.toml`, so runs may
  target it and fix rounds may push to its pull requests;
- the poll's `follow` list in `.github/poll/agent-board.json`, so its pull
  requests are followed, fixed and queued;
- optionally the `[unprotected_files]` `repos` list in both files, which
  lets runs edit `.github/` and every file the default list protects, all
  at once for every listed repository. tracker lists a repository there only
  once a ruleset on its `main` requires an approving review that is
  dismissed on push.
